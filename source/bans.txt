# The cases that end or hang the program every time on one machine: which case, which machine and versions, what
# breaks, the run that showed it, how to run it again and when it was last seen. On that machine the case is skipped
# as `banned`, the skip's detail naming its line here and what breaks; the mode word `unban` runs it anyway. The
# machine is the one the mode file's machine=<name>[@<version>] says, which the runners write (docs/Crashes.md); a run
# without that word holds no line. tools/bans.py checks every line and writes source/banlist.c from this file.
#
# A line per ban, its fields between |, in the header's order:
#   suite     the case's suite, as its line in the report names it
#   case      the case's name, as its line names it
#   machine   one of the machines below
#   versions  * for every version; a list of versions, comma separated (6a9235c22d, 10ed344); or bounds on a version
#             of dotted numbers: < V, <= V, >= V, > V, or a lower bound then an upper one (>= 1.2 < 1.4). A list or a
#             bound holds only for a run whose machine= word gives a version
#   breaks    what goes wrong, as it reads after the case's name: "ends the program with ..."
#   source    the run that showed it: the words, the date, the machine's version and the probe
#   retest    the mode words that run it again on that machine
#   checked   the date it was last seen and what was seen: 2026-11-07 ends on 6a9235c22d
#
# Machines: console eden ryujinx scarletnx scarletnx-android android
